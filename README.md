# ТЮФ / ТЮЕ — задачи

Веб-сервис для совместной работы над портфелем задач научных турниров школьников: **ТЮФ**, **ТЮЕ**, **конкурс капитанов** и смежные форматы.

Идеи поступают из рабочего Telegram-чата; отбор, формулирование и фиксация результатов ведутся в приложении до публикации официального списка турнира.

## Возможности

- **Реестр задач** — номер идеи, название, условие, автор, источники, формулировки, статус, проверка «своими руками», архив.
- **Теги (many-to-many)** — задача может относиться к нескольким направлениям одновременно (ТЮФ, ТЮЕ, Капитанка, SF4, SF3, Invent yourself и пользовательские теги). Новые теги создаются в настройках; у тега задаётся, нужна ли колонка методкомиссии на канбане.
- **Канбан** — отдельная доска на каждый тег (`/kanban/{slug}`). Задача с несколькими тегами отображается на каждой соответствующей доске. Статус у задачи один: перенос на одной доске меняет положение на остальных. Колонка «Методкомиссия» доступна, если у задачи есть хотя бы один тег с `has_metodkom`.
- **Карточка и список** — фильтры по тегу, статусу, автору и тексту; выгрузка TXT/CSV по текущему фильтру.
- **Вложения** — изображения и видео хранятся в SQLite (BLOB), отдаются inline с поддержкой HTTP Range.
- **Импорт** — разбор JSON-экспорта Telegram Desktop: идеи, комментарии, медиа, дедупликация уже обработанных сообщений.
- **Журнал изменений** — кто и что менял в полях задачи.
- **Учётки** — вход по логину/паролю; смена пароля в настройках. Начальные пароли из `.env` применяются только при первом создании пользователей.
- **Telegram-бот (опционально)** — уведомление в рабочий чат при создании задачи; раз в месяц — TXT-экспорт всех задач; **входящие** идеи и комментарии через личный чат с ботом (превью и подтверждение). Полный файл БД в чат не отправляется.

## Жизненный цикл задачи

1. Сообщение / идея в Telegram (или ручное создание на сайте).  
2. Формулировка перед отправкой.  
3. Методкомиссия — если позволяет набор тегов.  
4. Играется в турнире либо отклонена; при необходимости — архив («больше не предлагаем»).

Для задач в статусе «играется» фиксируются турнир, год и номер в списке; для Капитанки — этап (полуфинал / финал).

Дата на карточке: при **импорте** берётся время сообщения из экспорта; при **создании на сайте** по умолчанию подставляется текущее московское время (поле можно изменить вручную).

## Архитектура

Server-rendered приложение на FastAPI:

| Компонент | Решение |
|-----------|---------|
| HTTP и формы | FastAPI, Jinja2 |
| ORM | SQLAlchemy 2 |
| БД по умолчанию | SQLite (`data/zadachi.db`) |
| Сессии | cookie, `SessionMiddleware` |
| Канбан (UI) | SortableJS → `POST /api/tasks/{id}/status` |
| Импорт | `tg_import.py` + каталог `data/imports/` |
| Уведомления | Bot API (`httpx`), фоновые потоки |
| Деплой | Docker (`python:3.12-slim`), том `data/` |

Схема при старте дополняется миграциями в коде (колонки, сид тегов, однократный перенос со старого поля «назначение» при наличии). Перед работой создаётся локальная копия SQLite в `data/backups/`.

Каталог `data/` (БД, бэкапы, импорты) в git не входит.

## Стек

- Python 3.10+, FastAPI, Uvicorn, SQLAlchemy 2, Jinja2  
- `python-multipart`, `itsdangerous`, `python-dotenv`, `httpx`  
- SortableJS (CDN)  

## Конфигурация

Скопируйте `.env.example` → `.env`. Основные переменные:

| Переменная | Назначение |
|------------|------------|
| `SECRET_KEY` | Подпись сессионных cookie |
| `DATABASE_URL` | URL БД (по умолчанию SQLite в `data/`) |
| `PASS_*` | Начальные пароли пользователей при первом запуске |
| `TELEGRAM_BOT_TOKEN` | Токен бота (@BotFather) |
| `TELEGRAM_CHAT_ID` | Чат для уведомлений и TXT (для группы — отрицательный id) |
| `APP_BASE_URL` | Публичный базовый URL сайта без завершающего `/` (ссылки в уведомлениях) |
| `TELEGRAM_MONTHLY_DAY` | День месяца для автоотправки TXT (1–28, по умолчанию 1) |

Без `TELEGRAM_BOT_TOKEN` интеграции с ботом нет. Без `TELEGRAM_CHAT_ID` не уходят исходящие уведомления и TXT в рабочий чат; входящий приём в личке бота работает при наличии токена.

**Входящий поток:** см. краткую инструкцию [`docs/telegram-bot.md`](docs/telegram-bot.md). Сообщение в чате идей → превью автору в личку → «Сохранить». Нужен `/start` у бота; в @BotFather — `/setprivacy` → Disable.

Уведомление о новой задаче включает: номер идеи, название, теги, автора, пользователя, сохранившего запись, время создания на сайте (МСК), полное условие, источники, ссылку на карточку (если задан `APP_BASE_URL`), вложения к условию (в пределах лимита Bot API). При пакетном импорте в чат уходит сводка, а не сообщение на каждую строку.

Полный бэкап SQLite на сервере — за счёт тома `data/` и копий в `data/backups/`, не через Telegram.

## Запуск

Локально:

```bash
cp .env.example .env
# задайте SECRET_KEY и PASS_*; при необходимости — параметры Telegram
./run.sh
```

Приложение: `http://127.0.0.1:8000`.

Docker:

```bash
docker build -t tyuf-tyue-zadachi .
docker run -p 8000:8000 \
  -e SECRET_KEY=… \
  -e TELEGRAM_BOT_TOKEN=… \
  -e TELEGRAM_CHAT_ID=… \
  -e APP_BASE_URL=https://example.com \
  -v "$(pwd)/data:/app/data" \
  tyuf-tyue-zadachi
```

На сервере обязательно смонтировать `data/`, иначе БД и вложения пропадут при пересоздании контейнера. После смены `.env` процесс нужно перезапустить (перезагрузка страницы в браузере конфиг не подхватывает).
